Beyond TablePlus

Workflows that usually need a second tool

DB Desk follows the TablePlus model — connections, a grid, SQL tabs — then adds the things you would otherwise script, bolt on, or do by hand.

Reveal encrypted columns in place

Store a per-connection AES key — raw, base64: Laravel APP_KEY, or a passphrase — and name the encrypted columns. AES-256-GCM/CBC envelopes are detected and decrypted inside the grid behind a Decrypt toggle. The key stays encrypted at rest and is never sent to the AI.

Timestamps in your timezone

Pick a display timezone, and say how naive timestamps are stored. Both plain timestamp columns and timestamptz render in your zone, and filter values convert back automatically when you query.

Ask AI — read-only, always

Ask a question in plain language; DB Desk sends the current table and column names, gets back one SELECT, runs it read-only and shows the SQL with the rows. It is a chat: follow up and the previous SQL is carried into the next request.

One question across databases

When a question spans connections, the agent requests the missing schemas, returns one read-only statement per database plus a join — then DB Desk loads each result into an in-memory SQLite database and runs the join locally.

SQL editor that knows your schema

Syntax highlighting plus alias-aware, join-aware, fuzzy-ranked autocomplete: c. completes to that alias’s columns, schema qualifiers and functions included. ⌘Space completes on demand.

Mongo and Redis, same guards

Collections, documents, a raw filter object, an aggregate tab; keys, TTL, a type-aware value drawer and a command console. They share the same read-only guards, production approvals and audit trail as your SQL tables.

Query work

A SQL tab that finishes your sentences

Open as many tabs as the question needs, each with its own result set. The editor understands aliases and joins, so completion follows the statement you are writing rather than a flat list of every column in the database.

  • Alias-aware completion: c. → that table’s columns
  • Fuzzy ranking, functions and schema qualifiers
  • ⌘⏎ runs, ⌘S saves, saved queries come back as buttons
  • AI autocomplete on ⌘I, with an opt-out in Settings

Reading data

Filters, limits and edits that behave

Per-column operators build the WHERE clause without touching the SQL, and the limit control decides how much of a large table you pull. Double-click a cell to edit it; JSON cells get a proper editor, encrypted columns get a Decrypt toggle.

  • Filter by column, operator and value — or search the page with ⌘F
  • Right-click a table: open, export CSV/JSON/SQL, copy name, drop (with arming)
  • Every write on a PROD connection asks first, and is logged

AI that stays in its lane

Schema in, answers out — never your rows

Point DB Desk at any OpenAI-compatible endpoint. It sends the SQL you are writing, the dialect, and the names and types of the tables in play. Row data, passwords, tokens and SSH material are not part of the request, and per-connection switches let you hide a schema from the model entirely or keep it inspect-only.

  • AI can see this schema — off means the model never learns it exists
  • AI can run read-only queries — off keeps it to suggestions
  • Every statement the agent runs is written to the audit log
  • API keys are AES-GCM encrypted at rest, in the app’s own data folder

Security model

Local-first, read-only-first

DB Desk is a Tauri shell around a local Python sidecar. The sidecar serves the UI and talks to your databases; nothing else is in the path.

Read-only is the default, and enforced server-side

The guard lives in the API the UI calls, so hiding a button is not the protection.

Credentials are encrypted at rest

Secrets sit in the app’s data folder under AES-GCM. They are never printed, never synced, and never part of an AI request.

Production asks before it writes

Writes against a PROD connection queue in an approval drawer; the audit log records what ran, where, and for what.

No account, no backend, no telemetry

The only outbound calls are the ones you configure: your database, your AI endpoint, and the signed updater.

Read the security model — what leaves your machine, measured, with the script to check it yourself.
